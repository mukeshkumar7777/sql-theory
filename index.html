Module 1: SQL Subsets (DDL, DML, DQL, DCL, TCL) Schema & Transactions
01.Data Definition Language (DDL)
Auto-Commits Instantly
Student Intuition: DDL commands define or alter the physical structure of tables and schemas. They write metadata directly to the database catalog and cannot be rolled back in most database engines.
Example CREATE, ALTER, DROP, TRUNCATE
-- 1. CREATE: Define a new relation with constraints
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    gpa DECIMAL(3,2) CHECK (gpa >= 0.0)
);

-- 2. ALTER: Modify schema by adding a column with default value
ALTER TABLE students ADD COLUMN email VARCHAR(255) DEFAULT 'pending@college.edu';

-- 3. TRUNCATE: Deallocates data pages (fast, resets auto-increment, keeps schema)
TRUNCATE TABLE students;

-- 4. DROP: Permanently removes data, indexes, and schema
DROP TABLE students;
02.Data Manipulation (DML) & Data Query (DQL)
Row Operations
Student Intuition: DML modifies data rows inside existing tables and runs inside transactions (can be rolled back). DQL retrieves records without modifying database state.
Example INSERT, UPDATE, DELETE & Safe UPSERT
-- INSERT: Add individual records
INSERT INTO students (student_id, name, gpa) VALUES (101, 'Alice', 3.85);

-- UPDATE: Modify existing rows based on a predicate
UPDATE students SET gpa = 3.95 WHERE student_id = 101;

-- DELETE: Remove specific rows (can be rolled back)
DELETE FROM students WHERE gpa < 2.0;

-- UPSERT (ON CONFLICT): Update if already exists, else insert
INSERT INTO students (student_id, name, gpa) VALUES (101, 'Alice', 4.00)
ON CONFLICT (student_id) DO UPDATE SET gpa = EXCLUDED.gpa;
03.Transaction Control (TCL) & Data Control (DCL)
Security & Atomicity
Student Intuition: TCL manages atomicity via transaction boundaries. DCL controls role permissions and security grants.
Example Transaction with Partial Rollback via SAVEPOINT & Permission Grants
-- TCL: Atomic multi-step operation with savepoint
BEGIN;
UPDATE accounts SET balance = balance - 500 WHERE account_id = 1;
SAVEPOINT debit_done;

UPDATE accounts SET balance = balance + 500 WHERE account_id = 2;
-- If error occurs: ROLLBACK TO SAVEPOINT debit_done;
COMMIT;

-- DCL: Role-based permissions
GRANT SELECT, INSERT ON students TO analyst_role;
REVOKE INSERT ON students FROM analyst_role;
Module 2: Complete Relational Joins Encyclopedia All Join Types
04.1. INNER JOIN (Equi-Join & Non-Equi Join)
Exact Intersection
Student Intuition: Returns rows only when the join condition evaluates to true in both tables. Discards all non-matching records.
Equi-Join Example Matching Primary and Foreign Keys
SELECT e.name AS emp_name, d.dept_name
FROM employees e
INNER JOIN departments d ON e.department_id = d.id;
Non-Equi Join Example Joining on Value Ranges (>=, <=) 
-- Match employees to salary grades where salary falls between min and max bounds
SELECT e.name, e.salary, g.grade_level
FROM employees e
INNER JOIN salary_grades g 
    ON e.salary BETWEEN g.min_salary AND g.max_salary;
05.2. LEFT JOIN & 3. RIGHT JOIN
Outer Directional Joins
Student Intuition:
  • LEFT JOIN: Keeps all rows from the left table. If no match exists on the right, right columns fill with NULL.
  • RIGHT JOIN: Keeps all rows from the right table, filling unmatched left columns with NULL. (In industry, LEFT JOIN is preferred for readability).
LEFT JOIN Example All Customers Regardless of Order History
SELECT c.name, o.order_id, o.total_amount
FROM customers c
LEFT JOIN orders o ON c.id = o.customer_id;
RIGHT JOIN Example All Departments Regardless of Assigned Employees
SELECT e.name, d.dept_name
FROM employees e
RIGHT JOIN departments d ON e.department_id = d.id;
06.4. FULL OUTER JOIN
Complete Union of Datasets
Student Intuition: Combines LEFT JOIN and RIGHT JOIN. Preserves all rows from both tables, filling with NULL wherever a relationship does not exist.
Example Finding Unlinked Records Across Both Entities
-- Retains employees without departments AND departments with zero employees
SELECT e.name AS emp_name, d.dept_name
FROM employees e
FULL OUTER JOIN departments d ON e.department_id = d.id;
07.5. CROSS JOIN & 6. SELF JOIN
Cartesian Products & Hierarchies
Student Intuition:
  • CROSS JOIN: Cartesian product ($N \times M$ rows). Multiplies every row of table A by every row of table B.
  • SELF JOIN: Joining a table to itself using two distinct aliases to evaluate intra-table hierarchies.
CROSS JOIN Example Generating Permutations (All Sizes x All Colors)
SELECT s.size_label, c.color_name
FROM sizes s
CROSS JOIN colors c;
SELF JOIN Example Finding Employees Earning More Than Their Managers
SELECT 
    e.name AS employee_name, e.salary AS emp_salary,
    m.name AS manager_name, m.salary AS manager_salary
FROM employees e
JOIN employees m ON e.manager_id = m.emp_id
WHERE e.salary > m.salary;
08.7. Anti-Join, 8. Semi-Join & 9. NATURAL JOIN
Special Join Architectures
Student Intuition:
  • Anti-Join: Identifies records in table A that have no matching rows in table B (LEFT JOIN ... WHERE B.id IS NULL).
  • Semi-Join: Returns rows from table A if they exist in table B, without duplicating rows if table B has multiple matches (EXISTS).
  • NATURAL JOIN: Automatically matches all columns with identical names across tables. (Interviewers warn against this because schema changes break queries silently).
Anti-Join Example Customers with Zero Orders
SELECT c.id, c.name
FROM customers c
LEFT JOIN orders o ON c.id = o.customer_id
WHERE o.id IS NULL;  -- Anti-join filter
Semi-Join Example Customers Who Placed at Least One Order
SELECT c.id, c.name
FROM customers c
WHERE EXISTS (
    SELECT 1 FROM orders o WHERE o.customer_id = c.id
);
NATURAL JOIN Example Implicit Column Matching
-- Joins implicitly on identical column names (e.g. department_id)
SELECT * FROM employees NATURAL JOIN departments;
Module 3: Aggregation, Grouping & Set Operations Calculations & Combining Sets
09.GROUP BY, HAVING, ROLLUP & CUBE
Multi-Dimensional Aggregates
Student Intuition:
  • ROLLUP produces hierarchical subtotals and a grand total.
  • CUBE computes all possible cross-dimensional combinations of subtotals.
  • HAVING filters groups; WHERE filters individual rows before grouping.
Example Multi-Tier Regional Sales Subtotals using ROLLUP
SELECT region, product_category, SUM(revenue) AS total_revenue
FROM sales
GROUP BY ROLLUP (region, product_category);
-- Returns: (Region + Category totals), (Region subtotals), and (Grand Total)
10.Set Operations (UNION, UNION ALL, INTERSECT, EXCEPT)
Set Mathematics
Student Intuition: Stacks queries vertically. Column counts and data types must match.
Example Practical Set Comparisons 
-- 1. UNION: Combines and removes duplicate records (triggers sorting)
SELECT city FROM suppliers UNION SELECT city FROM customers;

-- 2. UNION ALL: Combines without deduplication (much faster)
SELECT city FROM suppliers UNION ALL SELECT city FROM customers;

-- 3. INTERSECT: Cities where BOTH suppliers and customers exist
SELECT city FROM suppliers INTERSECT SELECT city FROM customers;

-- 4. EXCEPT / MINUS: Cities with suppliers but ZERO customers
SELECT city FROM suppliers EXCEPT SELECT city FROM customers;
Module 4: Window Functions & Analytical SQL Analytical Ranking
11.Ranking: ROW_NUMBER, RANK, DENSE_RANK, NTILE
Most Asked Interview Topic
Student Intuition:
  • ROW_NUMBER(): Unique sequential integers (1, 2, 3, 4).
  • RANK(): Tied values get identical ranks; skips the next rank (1, 2, 2, 4).
  • DENSE_RANK(): Tied values get identical ranks; does not skip numbers (1, 2, 2, 3).
  • NTILE(k): Splits sorted dataset into $k$ equal buckets (e.g., quartiles, percentiles).
Example Comparison of All 4 Ranking Functions
SELECT 
    name, department_id, score,
    ROW_NUMBER() OVER (PARTITION BY department_id ORDER BY score DESC) AS row_num,
    RANK()       OVER (PARTITION BY department_id ORDER BY score DESC) AS rnk,
    DENSE_RANK() OVER (PARTITION BY department_id ORDER BY score DESC) AS dense_rnk,
    NTILE(4)     OVER (PARTITION BY department_id ORDER BY score DESC) AS quartile
FROM test_results;
12.LEAD, LAG, FIRST_VALUE & Window Frames
Time-Series & Deltas
Student Intuition:
  • LAG(col, 1) accesses the previous row; LEAD(col, 1) accesses the next row.
  • FIRST_VALUE(col) / LAST_VALUE(col) fetch boundaries in a window frame.
  • ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW evaluates running accumulations.
Example Day-over-Day Growth & 3-Day Moving Average
SELECT 
    txn_date, amount,
    -- 1. Day-over-Day Delta
    amount - LAG(amount, 1) OVER (ORDER BY txn_date) AS dod_change,
    -- 2. Running Total
    SUM(amount) OVER (
        ORDER BY txn_date 
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS running_total,
    -- 3. 3-Day Moving Average (Current day + 2 previous days)
    AVG(amount) OVER (
        ORDER BY txn_date 
        ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
    ) AS moving_avg_3d
FROM transactions;
Module 5: Built-in Functions, Pivots & NULL Handling Data Transformation
13.String, Date, Math & NULL Safeguards
Scalar Operations
Student Intuition: Essential utility functions for parsing raw values, computing durations, and preventing runtime errors (such as dividing by zero).
Example String Manipulation & Substring Parsing
SELECT 
    CONCAT_WS(', ', last_name, first_name) AS formatted_name,
    SUBSTRING(email FROM 1 FOR POSITION('@' IN email) - 1) AS username,
    TRIM(BOTH ' ' FROM phone_number) AS clean_phone
FROM users;
Example Date Math & Divide-by-Zero Guard
SELECT 
    order_id,
    -- Date arithmetic: Age in days
    CURRENT_DATE - order_date AS days_elapsed,
    -- NULLIF converts 0 to NULL, avoiding divide-by-zero errors
    revenue / NULLIF(units_sold, 0) AS unit_price
FROM sales_orders;
14.CASE Expressions & Pivoting Rows into Columns
Cross-Tabulation
Student Intuition: Conditional aggregation pairs SUM(CASE WHEN ...) with GROUP BY to pivot categorical rows into separate columns.
Example Quarterly Revenue Pivot Table
SELECT 
    product_name,
    SUM(CASE WHEN quarter = 'Q1' THEN sales ELSE 0 END) AS q1_sales,
    SUM(CASE WHEN quarter = 'Q2' THEN sales ELSE 0 END) AS q2_sales,
    SUM(CASE WHEN quarter = 'Q3' THEN sales ELSE 0 END) AS q3_sales,
    SUM(CASE WHEN quarter = 'Q4' THEN sales ELSE 0 END) AS q4_sales
FROM quarterly_sales
GROUP BY product_name;
Module 6: Top 3 Placement Problem Patterns Interview Coding Round
Pattern 1.Find N-th Highest Salary (3 Implementations)
Asked in 90% of Interviews
Student Intuition: Always handle duplicate salaries using DENSE_RANK() or DISTINCT so ties receive the same rank.
Method A: DENSE_RANK() (Recommended Standard)
WITH RankedSalaries AS (
    SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk
    FROM employees
)
SELECT DISTINCT salary FROM RankedSalaries WHERE rnk = 2;  -- Change '2' to N
Method B: Correlated Subquery (Universal ANSI SQL)
SELECT DISTINCT salary
FROM employees e1
WHERE 2 = (  -- Change '2' to N
    SELECT COUNT(DISTINCT salary)
    FROM employees e2
    WHERE e2.salary >= e1.salary
);
Method C: LIMIT / OFFSET
SELECT DISTINCT salary 
FROM employees 
ORDER BY salary DESC 
LIMIT 1 OFFSET 1;  -- OFFSET is (N - 1), so OFFSET 1 = 2nd highest
Pattern 2.Department-wise Top 3 Earners
LeetCode Benchmark
Student Intuition: Partition by department and order by salary descending within a CTE, then filter the calculated rank.
Solution Complete Query
WITH DeptRanks AS (
    SELECT 
        d.dept_name, e.name AS employee_name, e.salary,
        DENSE_RANK() OVER (
            PARTITION BY e.department_id 
            ORDER BY e.salary DESC
        ) AS rank_in_dept
    FROM employees e
    JOIN departments d ON e.department_id = d.id
)
SELECT dept_name, employee_name, salary
FROM DeptRanks
WHERE rank_in_dept <= 3;
Pattern 3.Consecutive Login Streaks (Gaps & Islands)
Advanced Placement Problem
Student Intuition: Subtracting a row number from consecutive calendar dates produces a constant group anchor date for the entire active streak.
Solution Find Users with 3+ Consecutive Active Days
WITH DedupedLogins AS (
    SELECT DISTINCT user_id, login_date FROM user_logins
  ),
  StreakGroups AS (
    SELECT 
        user_id, login_date,
        login_date - (ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_date) * INTERVAL '1 day') AS streak_anchor
    FROM DedupedLogins
  )
SELECT 
    user_id, 
    MIN(login_date) AS streak_start, 
    MAX(login_date) AS streak_end, 
    COUNT(*) AS streak_length
FROM StreakGroups
GROUP BY user_id, streak_anchor
HAVING COUNT(*) >= 3;
Module 7: DBMS Internals, Indexes & Normalization Architecture & Theory
15.ACID Properties & Transaction Isolation Levels
Core DBMS Theory
Student Intuition: ACID governs transaction integrity:
  • Atomicity: All modifications succeed or all roll back.
  • Consistency: Preserves all declarative constraints and foreign key references.
  • Isolation: Concurrent transactions run safely without reading uncommitted intermediate states.
  • Durability: Committed data persists across system crashes and power failures.
Isolation Level Dirty Read Non-Repeatable Read Phantom Read
READ UNCOMMITTED Allowed Allowed Allowed
READ COMMITTED Prevented Allowed Allowed
REPEATABLE READ Prevented Prevented Allowed (Engine-dependent)
SERIALIZABLE Prevented Prevented Prevented
16.Clustered vs. Non-Clustered Indexes & SARGability
Performance Tuning
Student Intuition:
  • Clustered Index: Dictates the physical storage order of rows on disk (only 1 per table).
  • Non-Clustered Index: A separate lookup structure of pointers to the underlying data rows.
  • SARGable (Search Argument Able): Conditions that allow direct B-Tree index seeks. Applying functions to indexed columns prevents seeks and forces full table scans.
Example Non-SARGable vs. SARGable Query Design
-- ❌ Non-SARGable: Wrapping indexed column in function forces a Full Table Scan
SELECT * FROM orders WHERE EXTRACT(YEAR FROM order_date) = 2024;

-- ✅ SARGable: Column is untouched; uses B-Tree Index Seek
SELECT * FROM orders 
WHERE order_date >= '2024-01-01' AND order_date < '2025-01-01';
17.Database Normalization (1NF, 2NF, 3NF, BCNF)
Schema Design
Student Intuition: Normalization minimizes redundancy and prevents insertion, update, and deletion anomalies.
  • 1NF: Atomic values per cell (no lists), primary key defined.
  • 2NF: 1NF + no partial dependencies (every non-key attribute depends on the whole primary key).
  • 3NF: 2NF + no transitive dependencies ($A \rightarrow B \rightarrow C$). Non-keys must depend only on the primary key.
  • BCNF: Stricter 3NF: for every functional dependency $X \rightarrow Y$, $X$ must be a super key.
Example 3NF Transformation (Eliminating Transitive Dependencies)
-- ❌ Violates 3NF: zip determines city and state (transitive dependency via customer_id -> zip)
-- customers(id, name, zip, city, state)

-- ✅ 3NF Compliant: Normalized Lookup Structure
CREATE TABLE zip_directory (
    zip VARCHAR(10) PRIMARY KEY,
    city VARCHAR(50),
    state VARCHAR(50)
);

CREATE TABLE customers (
    id INT PRIMARY KEY,
    name VARCHAR(100),
    zip VARCHAR(10) REFERENCES zip_directory(zip)
);
18.Views, Stored Procedures & Triggers
Server-side Objects
Student Intuition: Server-side database objects that encapsulate business rules, security layers, and automated event hooks.
1. View with Check Option Security & Validation Layer
CREATE VIEW active_students AS
SELECT id, name, status FROM students WHERE status = 'active'
WITH CHECK OPTION; -- Blocks any INSERT/UPDATE that would set status != 'active'
2. Audit Trigger Event Hook for Automated Logging
CREATE OR REPLACE FUNCTION log_student_deletions() RETURNS TRIGGER AS $$
BEGIN
    INSERT INTO audit_log (table_name, record_id, deleted_at)
    VALUES ('students', OLD.id, NOW());
    RETURN OLD;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER student_delete_trigger
AFTER DELETE ON students
FOR EACH ROW EXECUTE FUNCTION log_student_deletions();
